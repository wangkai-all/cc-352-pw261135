# 虚构填报门户 · 自动填报与独立核对演示

> **声明**：本仓库是虚构演示。门户、账号、企业、数据、回执均为虚构，不对应任何真实身份或真实业务平台，回执无法律效力。

演示一条完整的“自动填报”链路，并回答三个工程问题：

1. **草稿 ≠ 申报完成**：门户自动保存草稿，正式提交是独立动作，只有拿到回执才算完成。
2. **恢复时不能无脑重提**：复用草稿前先比对内容与组织归属；被人改过、提交响应丢失、浏览器换账号，都有明确的处置策略。
3. **结果可核对**：自动程序把门户回执送入**独立核对服务**，核对服务不信任自报，独立回查门户确认。

## 组件

| 组件 | 位置 | 端口 | 说明 |
|---|---|---|---|
| 虚构填报门户 | `portal/` | 4101 | 登录、自动保存草稿、正式提交、回执、故障注入 |
| 独立核对服务 | `verifier/` | 4102 | 接收回执并独立回查门户；结果看板在此 |
| 自动填写程序 | `automation/` | — | Playwright 真实驱动浏览器，读待报数据、填表、提交、上交回执 |
| 共享定义 | `shared/` | — | 两个表单版本（v1/v2）、内容指纹算法 |

## 快速开始

```bash
npm install
npx playwright install chromium   # 首次需要下载浏览器
npm run demo                      # 起服务 + 重置场景 + 跑一轮自动填报
```

> 无 root 权限的最小容器里，浏览器可能因缺系统库无法启动。运行
> `bash scripts/install-browser-libs.sh` 会把依赖库下载解包到 `data/browser-libs`，
> 自动程序启动浏览器时自动加载（无需 root）。

然后打开：

- 门户（人工视角）：http://127.0.0.1:4101 （`alpha` / `demo1234`，或 `beta` / `demo1234`）
- 结果看板（核对侧）：http://127.0.0.1:4102 —— 展示**字段差异、待核验事项、最终回执**

停止服务：`npm run stop`。单独运行自动程序：`npm run automate -- --account alpha`。

## 一轮演示覆盖的场景

`scripts/seed.mjs` 预置 8 条记录，`automation/run.js` 逐条处理：

| 记录 | 场景 | 预期行为 |
|---|---|---|
| DECL-2026-0001 (v1) | 全新记录 | **整单重填** → 提交 → 回执核验一致 |
| DECL-2026-0002 (v2) | 全新记录（第二表单版本） | 整单重填 → 提交 → 核验一致 |
| DECL-2026-0003 (v2) | 有本账号此前保存的旧草稿 | 比对后**字段级续填**（只回填差异字段）→ 提交 |
| DECL-2026-0004 (v1) | 草稿被同事账号改过 | **不覆盖、不提交**，差异上报为待核验事项 |
| DECL-2026-0005 (v2) | 提交后门户“丢失响应”（故障注入） | 查询状态确认已受理，**恢复回执且不重复提交** |
| DECL-2026-0006 | 门户表单版本与待报数据不一致 | 终止，转人工 |
| DECL-2026-0007 | 记录归属另一组织 | 组织归属校验拦截，禁止提交 |
| DECL-2026-0008 (v1) | 草稿与待报数据完全一致 | **不填任何字段**，直接提交 |

再跑一次 `npm run automate`，可观察**断点恢复**：已提交的直接取回既有回执，未提交且草稿一致的直接提交。

## 恢复时的决策矩阵（整单重填 vs 字段级续填）

自动程序对每条记录先做三项只读检查（身份 → 组织归属 → 门户状态），再决策：

| 门户侧状态 | 决策 |
|---|---|
| 当前登录组织 ≠ 数据归属组织 | **终止**（ORG_MISMATCH），禁止任何写操作 |
| 门户表单版本 ≠ 待报数据版本 | **终止**（VERSION_MISMATCH），转人工 |
| 已提交且内容指纹一致 | 不重复提交，直接采用既有回执 |
| 无草稿 / 草稿为空 | **整单重填** |
| 草稿是本人所存、有差异 | **字段级续填**：只回填差异字段，保存后校验内容指纹再提交 |
| 草稿与待报数据完全一致 | 直接提交 |
| 草稿被他人修改且有差异 | **终止**（DRAFT_MODIFIED_BY_OTHER），差异上报，待人工核验 |

选择“字段级续填”而非一律整单重填的原因：续填保留他人/历史的合法修改痕迹、缩小写操作面；但**前提是草稿归属清晰（本人所存）且差异可解释**。归属不清（他人改过）时一律停手转人工，而不是用待报数据覆盖。

## 故障控制

- **幂等提交**：幂等键 = `decl-<记录号>-<内容指纹前12位>`，同一内容重复提交返回同一回执；不同内容提交已受理记录返回 409 + 既有回执。
- **响应丢失恢复**：提交请求网络失败后**不立即重试**，先查门户状态——已受理则恢复回执；未受理才用同一幂等键重试（最多 2 次）。
  值得一提的是，“响应丢失”有两层：浏览器传输层会自动重发被掐断的请求（同一幂等键使重发安全返回同一回执，页面无感知）；只有持续丢失才会进入应用层的“查询状态再恢复”路径。本演示的故障注入按持续丢失实现（重发也丢弃），两条路径因而都被覆盖。
- **乐观并发**：提交携带草稿版本号，提交前草稿被他人改动 → 409，程序停手转人工。
- **内容指纹把关**：保存草稿后、点击提交前，都比对 SHA-256 内容指纹，不一致不提交。
- **身份守卫**：浏览器未登录或账号被换掉 → 重新登录并记录事项；组织归属不符 → 硬终止。
- **故障注入**（演示用）：门户 `/api/chaos` 可让指定记录“提交响应持续丢失”或“草稿保存失败”；门户记录列表页有对应按钮。

## 独立核对

自动程序把回执 POST 到核对服务后，核对服务用服务令牌调门户只读接口 `/api/service/records/:id` 独立回查，比对回执编号、内容指纹、组织归属，结论为 `VERIFIED / MISMATCH / PENDING`。看板（http://127.0.0.1:4102）汇总：每条记录的决策、字段差异表、待核验事项、最终回执与核验结论。

## 目录结构

```
filing-demo/
├── shared/            # 表单版本定义、内容指纹、存储、env
├── portal/            # 虚构填报门户（Express + 原生前端）
│   └── public/        # 登录页 / 记录列表(含故障注入面板) / 表单页
├── verifier/          # 独立核对服务 + 结果看板
├── automation/        # Playwright 自动填写程序
│   ├── pending-data.json   # 待报数据（虚构）
│   └── accounts.json       # 演示账号
├── scripts/           # 场景种子、一键演示、停止
└── data/              # 运行时状态（gitignore）
```

## 常用命令

```bash
npm run portal        # 只起门户

npm run seed          # 重置并预置演示场景
npm run automate -- --account alpha                 # 跑全部待报记录

```

## 边界与说明

- 所有接口均无真实业务语义；`/api/admin/*`、`/api/chaos` 未鉴权，仅用于本机演示。
- 存储为 JSON 文件（`data/`），非生产方案。
- 真实落地还需：真实身份认证与授权、验证码/反爬合规、审计日志、数据加密、与真实平台的变更适配等，均不在本演示范围。
